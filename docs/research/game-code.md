# Game code

What the original .swf holds, how its code is laid out, how content is defined, and how it saves. Source: the decompiled code in `decompiled/PeacefreeKong/scripts/` (to-do 1) unless an entry says otherwise. Numbers marked (measured) were measured; the rest are counts from the code.

## The file (measured)
- One .swf: LZMA-compressed (`ZWS`), SWF version 23, 7,463,597 bytes uncompressed. ActionScript 3.
- Not obfuscated (readable names), no embedded .swf, no active sitelock.

## Startup and rendering
- Frame 1 is `StarlingPreloader` (logo and loading bar); frame 2 holds the rest. The preloader starts Starling 1.4.1 with `game.peacefree.PeacefreeGame` as the root class.
- Starling draws on the GPU through Stage3D, at 60 fps (`GameConfig` default).
- Game size 800x540, the same as the SWF stage: `StarlingPreloader` calls `GameConfig.setScreenResolution(800,540,...)` at startup (`StarlingPreloader.as:38`). Corrected in to-do 2: to-do 1 said 2272x1280, which is only the default in `GameConfig`.
- Game version "Ver.1.08". Build flags in `game/container/GameConfig.as`: KONG_VERSION true, GLOEBIT_VERSION false, DEBUG_MODE, CHEAT_MODE and ENABLE_SITELOCK false. DEBUG_MODE and CHEAT_MODE are read nowhere in the decompiled code (to-do 3), so there is no hidden cheat or unlock to switch on.
- Window resize (to-do 3, measured in the projector): resizing the projector window makes Windows reset the graphics device. Starling's `handleLostContext` is off in the original, so Starling stops and shows "Fatal error: The application lost the device context!" on a white screen; the projector keeps running. The original does the same: same Starling setup, and its window showed the same red bar (only seen in a small capture). Fixed in v04 by turning `handleLostContext` on in `src/StarlingPreloader.as`: the game keeps drawing after resizing (measured). Its costs, from Starling 1.4.1's code: textures keep a copy of their image for restoring (more memory, not measured), and the minimap's RenderTexture comes back blank until it is redrawn.
- The game doesn't scale with the window: `StarlingPreloader` sets `scaleMode` to `noScale` and `align` to top-left, so the 800x540 game stays in the top-left corner and a smaller window crops it.

## Code map (`decompiled/PeacefreeKong/scripts/`)
- `game/peacefree/` (96 classes): `PeacefreeGame` (root: screens, premium state, save and load), `Map` (2,634 lines: the battle map, commands, game rules), `Tile`, `Building` (1,930 lines), `Mob` (1,501 lines), `Player` (resources and troops), `Mission` with 13 objective types in `missions/`, 5 bosses in `mobs/`, `effects/`, and every UI panel in `interfaces/`.
- `game/acts/`: `Act1` to `Act11` and `DemoMap`, one class per campaign act.
- `game/library/`: `KongregateAPI`, `GloebitAPI`, `FileLibrary` (saves), `MapLibrary` (map parser), `SoundLibrary`, `JSONLibrary` (HTTP).
- `starling/`: the Starling library, third-party code.
- Top level: embedded-asset classes (`Assets`, `SoundAssets`, `Fonts`, `ParticleAssets`, `*_mp3`, `*_png`, `exmission*_txt`).

## How content is defined
- Levels are data plus code. Each act's tile map is an embedded text file (binaryData `exmissionN_txt`, 25x25 tiles): rows split by newline, tiles by `;`, fields by `:` in this order: tile type, building, decor, danger, food, minerals, recruits, lock ID, secured, scouted, scouted-nearby, secured-nearby, then optional rescued and visible (`Map.loadMap`). The start point, objectives, story dialogue and scripted events are code in the act's class.
- Act to map: Act1 exmission18, Act2 11, Act3 12, Act4 13, Act5 14, Act6 16, Act7 17, Act8 7, Act9 9, Act10 8, DemoMap 4. Act11 (Endless Boss Run) builds a random map with `RandomMapGenerator`.
- Enemies are code only: about 25 numbered types as constants in `Mob.as` (`MOB_BIOSHIP = 1` and so on), with stats and behaviour in switch statements there; the 5 bosses have their own classes. `MobGenerator` spawns a mob type from a tile at an interval.
- Buildings are code only: numbered types with switch statements in `Building.as`.

## Save data
- Local Flash cookies (`SharedObject.getLocal` in `FileLibrary`): `game` holds unlocked acts, sound settings, best records, achievements and the Facebook/Twitter flags; `save-N` holds saved missions (`Map.as:2231`, slots in `SaveFileInteracer`).
- No server saves. Flash cookies are stored per site, so saves made on kongregate.com don't appear when the file is opened locally, and the other way round.
- Premium isn't in the save: [premium.md](premium.md).
- Flash keys a local file's save on the file's full path, file name included, because `getLocal` gets no `localPath` (`FileLibrary.as:15`). So in the original and v01-v04, every build has its own save, and each new build starts at the tutorial again. Measured in to-do 3: the projector's save folder has separate `game.sol` files under `.../patched/PeacefreeKong-v01-fpsmeter.swf/` and `.../PeacefreeKong-v03-premium.swf/` (in `%APPDATA%\Macromedia\Flash Player\#SharedObjects\<random>\#localWithNet\`; the drive letter isn't in the path).
- From v05, all builds share one save: `src/game/library/FileLibrary.as` passes `"/"` as `localPath`, so the projector keeps `game.sol` (and `save-N.sol`) straight in `#localWithNet\`, wherever the build is and whatever its name. The original isn't patched and keeps its own save. Measured after the user's test: the projector wrote only `#localWithNet\game.sol`, with no per-file folder for v05 or a renamed copy of it in another folder. Every save and load goes through `FileLibrary.loadSharedData`; nothing else calls `getLocal` (to-do 5). The drawback: another local Flash game that also uses `getLocal("game", "/")` would share the file.
- Ruffle's web version keeps saves in `localStorage` as `<host><path>/<name>` without the port (measured, to-do 5): `127.0.0.1/game.swf/game` for v04 (under the file's path), `127.0.0.1//game` for v05. `check.py --shared-save` checks for the second.
- The game writes `game` whenever the campaign screen opens (`PeacefreeGame.as:649`), so `show_premium=true`, which starts there, makes it save within about a second (measured).
- A `.sol` file holds its own name in the header (`TCSO`, then the name's length and the name, here `game`), not its path; so copying one to another folder moves the save. To-do 5 copied v04's `game.sol` into `#localWithNet\` once. The saves before that (decoded, to-do 5): original none unlocked; v01 act 2, best 37 rescues and longest game 11; v03 act 2; v04 acts 2-11 (from "Unlock All Acts"), 5 kills, 4 rescues. No `save-N` files existed.
- Progress is the `unlockedActs` list: winning act N adds N+1 (`Act1.as:1722-1734` and the other acts); the campaign screen shows an act's button only if it's in the list (`CampaignActButton.as:46-61`). Medals for the Tech screen come from achievements (`SkillsInterfacer.as:183`).
- The only settings panel is the options menu inside a mission (`OptionsInterfacer`, opened from the mission's HUD): music, SFX, difficulty, Exit Game, Back to Game. v04 adds "Unlock All Acts" there. From v08 (v09: Settings first, the sound icons to its right) it also opens from a Settings button on the title and campaign screens (to-do 6): see "Sound and the settings panel".
- The save is AMF3 (measured, to-do 6, Ruffle's copy decoded from base64): a setting's name is followed by its value, for true/false `0x02` (false) or `0x03` (true), e.g. `bEnableFX` then `0x02` after SFX was switched off. `check.py --settings` reads it that way.
- The title screen also writes `game` as soon as it's made: its constructor calls `toggleSFX(false)` and `toggleBGM(false)`, which save (`TitleScreen.as:211-212`); a fresh Ruffle page has the `game` key while the title shows (measured).

## Sound and the settings panel (to-do 6, from the code)
- Sound on/off: `SoundLibrary.ENABLE_SFX` (static) and `PeacefreeGame.bEnabledBGM`; inside a mission `Map.bEnableBGM` is a copy, kept equal by `Map.setEnableBGM`. Both are saved in `game` as `bEnableFX` and `bEnabledBGM` (`PeacefreeGame.saveGameData`).
- Volume: music plays at a fixed 0.35 (`SoundLibrary.BGM_VOLUME`, applied in `playBGM`); sound effects at full volume (`playSFX` calls `sound.play()` without a SoundTransform). The playing music channel is private to `SoundLibrary`, so changing the volume of a playing track needs a patch there.
- From v10 (to-do 6 step B): `SoundLibrary` reads music and SFX volume (0-100) from a `settings` save when the class starts, plays sound effects at the SFX volume, and changes the playing track's volume when the music slider moves (a channel keeps a copy of the SoundTransform it was given, so the new one is assigned again). The save holds `content = {music, sfx}`; Ruffle writes them as AMF3 integers, `0x04` then the value (one byte up to 127): `music` then `04 4B` for 75 (measured). The mute flags stay in `game`.
- The slider (inside `OptionsInterfacer`, Starling 1.4.1, from the code): an invisible Quad catches the presses, because Starling's `hitTest` checks only `visible` and `touchable`, not alpha (`DisplayObject.as:189`); a touch that began on the slider keeps it as its target while the mouse leaves it (`Touch.isTouching` uses the bubble chain from the start), so a drag past either end still moves the knob to 0 or 100%.
- The title screen's music icon is at about (192, 17) in the 800x540 player, right of the SFX icon (measured on a v09 screenshot); `check.py --settings` clicks it.
- The title and campaign screens each have their own on/off icons, top left (`sfxButton`, `bgmButton`, with `toggleSFX` and `toggleBGM`, which update the icon, start or stop the menu music and save; from v13 pause or continue it, see "Music"); the mission HUD has its own (`MapHUD.toggleBGM`, `toggleSFX`).
- `pgame.map` isn't only the mission: the title screen puts its background demo map there (`TitleScreen.as:73-76`); the campaign screen has none (`transitionView` clears it). So "`pgame.map != null`" doesn't mean "in a mission"; v08's `OptionsInterfacer` gets its mode from its constructor instead (`inMission()`: Map passes no callback, the screens pass one).
- The campaign screen decides which act buttons show when it's made (`CampaignActButton`'s constructor sets `visible`); nothing refreshes them. v08's "Unlock All Acts" on the campaign screen therefore makes the screen again with `pgame.goToCampaignScreen()`, the game's own door animation (0.5 s doors, 0.5 s wait, then `transitionView`); the screen below stays clickable while the doors close, as everywhere in the game.
- Buttons call `pressedCallback` on touch "began", with the TouchEvent as argument (`Clickable.onPressed`); the game always passes anonymous functions, which accept the extra argument.
- `build.py` (ffdec `-replace`) can only replace classes that exist, so new UI such as the volume slider has to live inside an existing class (here `OptionsInterfacer`).

## Music (to-do 7, from the code unless marked)
- The game has four songs, embedded in the .swf and put in the sound cache at start (`SoundAssets.as:50-53`): `main_menu` (title and campaign screens), `act_2_0` and `act_2_1` (every act's mission list, `map.bgList`), `danger` (story parts in Act1 and Act8). `SoundLibrary.loadLibrary` is never called, so `links` stays empty and `playBGM`'s loading ("buffering") branch never runs: nothing loads while playing.
- Title and campaign: `PeacefreeGame.playBGM` plays `main_menu` when music is on and none plays; the song's end calls it again (a loop). `transitionView` keeps the song when going from the title to the campaign screen, stops it when a mission starts, and starts `main_menu` when a mission ends.
- Missions: `Map.progress` calls `Map.playBGM` every frame, which starts `bgList[bgIndex]` when music is on and none plays; a song's end moves `bgIndex` on. The original `setEnableBGM(true)` moved it on too, so unmute started the next song; a loaded save calls it (`Map.as:396`), so a loaded mission started with its second song. Story music changes (Act1, Act5, Act8) call `pauseBGM`, `stopBGM`, set a new `bgList` and `unpauseBGM` in one go, so `bPausedBGM` is never set between frames.
- The title's background demo map (`DemoMap`, no music of its own) keeps Map's default list, `"act_1"`, a song the game doesn't have; its `bEnableBGM` is a copy from when the title was made. So whenever no music plays (title muted), it calls `SoundLibrary.playBGM("act_1")` every frame, which stops the current channel and then finds no song: nothing is heard.
  - Wrong (Claude, 2026-10-31, while planning to-do 7): "muting on the title starts `act_1` one frame later". `act_1` isn't in the cache, so nothing plays (found in `SoundAssets.as` during the review).
- From v13: `SoundLibrary.pauseBGM` stops the song but remembers it, where it was (`SoundChannel.position`, ms) and its end function; `resumeBGM` plays it from there (`Sound.play(position)`); `stopBGM` and any new song forget it. A paused song counts as playing in `isBGMPlaying`, so the demo map's every-frame `playBGM("act_1")` (and `Map.playBGM`, `PeacefreeGame.playBGM`) don't make it forget the paused song. The mute icons (title, campaign, mission) and the panel's music slider pause and continue; screen changes and story music changes still stop for good. `Map.nextBGM` (the panel's Next, missions only) stops the song and starts the list's next one.
- `Map.as` (2,634 lines) recompiles unchanged with ffdec `-replace`, and the title check passes on that build (measured: a scratch build, 15 s).
- The headless check can't hear the music: Ruffle mixes sound inside WebAssembly, and the check sees only the picture and the saves. Whether a song continues or starts over is a projector test.
